# ECharts 经营看板与可信演示

## 本阶段解决的问题

API 能证明查询契约，但评审者通常希望在几分钟内看到业务结果。经营看板把技术链路转换为可理解的指标，同时保留数据口径、错误状态和明细核对入口。

看板回答四类问题：

1. 筛选时段内的成交额、有效订单量和客单价是多少？
2. 成交额和订单量如何随时间变化？
3. 哪些地区和渠道贡献更高？
4. 当前数据是否足够新，图表能否与分钟明细相互核对？

## 为什么不能在浏览器里聚合 500 条明细

分钟明细接口最多返回 500 行。如果浏览器直接对这些行求和，超过 500 行的查询会得到被截断的错误总数。当前设计为不同用途提供不同接口：

- `summary`：ClickHouse 对全部筛选数据求总体指标。
- `timeseries`：ClickHouse 按服务端选择的时间桶聚合趋势。
- `breakdown`：ClickHouse 按地区或渠道聚合排行。
- `minutes`：只用于展示最近明细，不参与 KPI 计算。

这是“查询口径正确”优先于“页面先画出来”的关键工程取舍。

## 时间桶策略

`bucket=auto` 根据范围选择聚合粒度：

| 查询范围 | 时间桶 |
| --- | --- |
| 不超过 6 小时 | 1 分钟 |
| 不超过 24 小时 | 5 分钟 |
| 不超过 7 天 | 15 分钟 |
| 7 至 31 天 | 1 小时 |

用户也可以显式指定时间桶，但预计点数超过 1500 时 API 返回 `422`，提示使用更粗的粒度。这个限制同时保护 ClickHouse、网络传输和浏览器渲染。

## 图表选择

- 趋势使用折线加柱状组合：GMV 是连续变化，订单量是离散计数，两者使用不同轴和不同形状。
- 地区使用横向柱状图：地区名称长度不同，横向布局比饼图更适合精确比较。
- 渠道数量较少，使用环形图展示构成，同时启用纹理模式，不只依赖颜色。
- 最近分钟指标使用表格，作为图表之外的可核对数据。

图表不会使用地图，因为当前核心问题是比较地区贡献，而不是分析空间邻接关系。

## 可访问性与响应式

- 页面使用语义化标题、表单标签、按钮和表格。
- ECharts 开启 ARIA 描述和 decal 纹理。
- 地区与渠道图提供可展开的数据表替代视图。
- 所有控件高度至少 44 像素，并保留可见键盘焦点。
- 页面尊重 `prefers-reduced-motion`，不会强制播放动画。
- 使用语义颜色变量支持亮色和暗色主题。
- 已在 375、768、1024、1440 像素宽度下检查，无横向页面溢出。

## 加载、空数据和错误状态

一次刷新会并行请求总体、趋势、地区、渠道和最近明细。刷新期间：

- 按钮进入禁用状态，避免重复提交。
- KPI 显示骨架状态，图表显示 ECharts loading。
- `aria-live` 向读屏软件报告成功或失败。

没有数据时返回 `200` 和空数组，看板展示空状态；ClickHouse 不可用时 API 返回 `503`，页面展示错误说明与重试按钮。两种情况不能混为一谈。

## 可信预览模式

没有 Docker 时运行：

```powershell
./scripts/dashboard-preview.ps1
```

预览仓库在内存中生成可重复的地区、渠道和分钟指标，支持真实筛选和聚合逻辑。API 通过 `X-Data-Mode: preview` 响应头声明来源；页面显示“演示数据 · 非实时”和醒目说明。

预览模式只能证明界面、接口契约和依赖注入设计，不能证明 Kafka、Flink 或 ClickHouse 已运行。这一边界必须在 README、演示和文档中保持一致。

## 供应链与页面安全

- ECharts 固定为 6.1.0，不使用浮动的 `latest`。
- CDN 脚本带 SHA-384 Subresource Integrity 校验和 `crossorigin=anonymous`。
- Dashboard 响应设置 Content Security Policy，只允许本站资源和固定 CDN 来源。
- 同时设置 `X-Content-Type-Options: nosniff` 与 `Referrer-Policy: no-referrer`。
- 浏览器请求 API 与页面同源，不需要放开通配符 CORS。

## 自动化验证

- Python 测试验证时间桶、维度白名单、响应模型、UTC 序列化、安全响应头和静态资源。
- 预览仓库测试验证固定时钟下数据可复现、筛选改变汇总结果、趋势顺序和维度排序。
- Node 内置测试验证金额字符串格式化、大整数显示、查询参数编码、快捷时间范围和错误提示。
- 浏览器验收验证 4 个响应式宽度、亮暗主题、减少动画、筛选刷新、图表 Canvas 和无横向溢出。

## 常见技术问题

### 为什么总体指标不从趋势点再次求和

时间序列可能因为时间桶、最大点数或未来采样策略发生变化。总体指标由独立汇总查询返回，可以保持明确口径，也避免浏览器重复实现聚合逻辑。

### 为什么维度列名不能像普通值一样参数绑定

ClickHouse 参数适合绑定值，列名属于 SQL 结构。服务端用 `region`、`channel` 白名单映射到固定列名；不接受任意字符串，因此既支持动态维度又不引入结构注入。

### 预览模式会不会让项目显得不真实

只要明确标注，它反而体现工程意识：评审者可以快速检查界面，而真实运行证据仍由 Docker 冒烟测试、远程 CI 和端到端结果单独提供。问题在于混淆证据，不在于提供预览。

### 为什么使用 CDN 而不是把 ECharts 整包提交到仓库

当前页面没有前端构建链，固定 CDN 加 SRI 能保持仓库轻量并限制供应链变化。代价是首次打开需要网络；如果后续需要完全离线演示，可在构建阶段把固定版本复制到静态目录并继续校验哈希。
